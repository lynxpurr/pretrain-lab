# Day 7 — SFT 数据 v2/v2b + LoRA + GGUF/Ollama demo（2026-11-19）

> 目标：Day 6 已把 SFT v1 的缺陷归因到**数据侧**（复读=罗列癖、校准缺失、格式跟随弱），本日做数据修正、重训、LoRA 对比与本地部署。
> 结论一句话：**SFT v2 把 rep-4 从 0.131 压到 0.066、校准/翻译/格式修好，但列表降采样误伤数学；v2b 用"数学保护"修回算术（3+5=8、7×6=42）却把 rep-4 抬回 0.117。最终部署选 v2（Q4_K_M）——综合对话质量最佳；v2b 作为消融证据保留。**

## 1. 数据侧供给实测（修正 HANDOFF 粗口径）

|---|---|---|---|

| 真正"承认不知道/纠正前提" | 不知道 9,438 / 不确定 23,564 / 尚未 5,786 / 没有官方 139 | 直接承认类 3,786 条，其中多为长推理中的"无法确定" | 必须**程序化生成**校准样本 |

## 5. SFT v2b（数学保护消融，`--protect-math`）

**动机**：v2 的列表降采样把长数学推理（恰好都是编号步骤）一起砍掉，导致 math-add/math-mul 算术回归。v2b 对**数学/推理样本**（用户句含数学关键词+数字，或答案含公式/等式）**豁免列表降采样**，非数学列表仍保留 1/5。

| 项 | 值 |
|---|---|
| 数据 | 250,001,408 token / 244,142 blocks / 监督 191,451,932 = **76.58%** / 列表类 **13.53%** / 数学列表类保留 **23,253** 条 / 557,651 条对话 |
| mask | 300 块 / 2,755 段 / 0 违规；val 同 v1 |
| 训练 | 3,815 步 / **1h19m23s** / 53,073 tok/s / peak 12.05GB / `EXIT:0` |
| **SFT val** | **1.5981**（略优于 v2 的 1.6038） |
| 评测 | 15/18（关键词）/ 16/18（语义）；rep-4 **0.117**（>0.08） |
| 结果 | **数学修回**（3+5=8、7×6=42 算术正确；math-mul 仍非纯数字）；但 **translate-en2zh / capability 回归**、rep-4 抬到 0.117 |
| 结论 | 不部署；作为"保护数学 ↔ 复读代价"的消融证据。Day 8 可做**选择性数学保护**（只保护短算术/截断长步骤）或加算术样本权重，争取两者兼得。 |

## 6. LoRA（r=8，v2 数据）

**实现**（`tools/lora.py` + `tools/sft.py --lora-*`）：冻结底座，把 qkv / proj / gate / up / down 包成 `LoRALinear`（A kaiming、B=0，初始增量 0）；训练结束 `merge_lora()` 把 `B·A·scaling` 加回 base 并保存为普通 `last.pt`（eval/deploy 无需改代码），另存 `adapter.pt`。

| 项 | 值 |
|---|---|
| 目标 / 秩 | qkv · proj · gate · up · down；r=8 / alpha=16 / scaling=2.0 |
| 可训练参数 | **1,671,168 / 139,518,720 = 1.20%**（<2% 判据） |
| 50 步冒烟 | loss **2.7086 → 2.5235**；val 2.0845；peak **9.76GB**；52,147 tok/s |
| **显存** | 全参 SFT v2 peak **12.05GB** → LoRA **9.74GB**（**省 2.3GB**） |
| **速度** | 全参 52,825 tok/s → LoRA 53,500~54,300 tok/s（略快 1~3%） |
| **磁盘** | 全参 ckpt 1.65GB（含 optimizer）→ LoRA wrapped ckpt **571MB**；adapter 6.7MB |

**lr 对照（关键）**：
- 2e-4（首跑，1000 步后停）：val 1.9464@250 → 1.9148@500 → 1.8954@750 → **1.8839@1000**；T0.7 采样在 step 1000 出现特殊 token/乱码/中英混杂。
- **5e-4 探针（500 步）**：val **1.9135@250 / 1.8974@500**（同 step 均优于 2e-4），但 T0.7 采样仍退化——**r=8 在 1 epoch 内学不稳 chat 模板**（容量/步数不足，非纯 lr 问题）。
- 决定：全量 1 epoch 用 **5e-4**（标准 LoRA 常用高 lr；2e-4 明显欠拟合）。

**全量 5e-4（1 epoch，3,815 步，`EXIT:0`）**：**1h17m50s / 54,124 tok/s / peak 9.74GB / final val 1.8253**；val 曲线 1.9145@250 → 1.8843@500 → 1.8574@1000 → 1.8303@2500 → **1.8253@3815**。

**与全参 v2 同题对比（greedy）**：

| 指标 | 全参 SFT v2 | **LoRA r8 5e-4** | 差异 |
|---|---|---|---|
| SFT val | **1.6038** | 1.8253 | +0.2215（LoRA 差） |
| 预训练 PPL | 16.185 | **15.690** | **LoRA 更少遗忘** |
| SFT PPL | **4.845** | 6.090 | LoRA 差 |
| 题库（关键词） | **15/18** | **15/18** | 持平，但失败项不同 |
| rep-4 ↓ | **0.066** | **0.260** | LoRA 明显更差 |
| distinct-2 ↑ | **0.854** | 0.623 | LoRA 更差 |
| 训练峰值显存 | 12.05GB | **9.74GB** | **-2.3GB** |
| 速度 | 52,825 tok/s | **54,124 tok/s** | +2.5% |
| ckpt | 1.65GB | **526MB merged / 6.5MB adapter** | -68% / -99.6% |

**LoRA 失败项**：`math-mul` 28（算术错）、`translate-en2zh` 英文重复、`refuse-unknown` 编造"2027 德国队"；`en-fluency` 仍拒答。**结论**：LoRA r=8 / 1.20% 在 1 epoch 内**欠拟合**（SFT fit/复读/校准都落后），但**显存/磁盘/速度 + 预训练遗忘**占优；**不部署**。Day 8 试 **r=12（≈1.80%）或 2 epochs**，用单变量对照看能否把 rep-4/校准拉回。

> 结论：LoRA 的**显存/磁盘优势明确**（-2.3GB / ckpt -68%），速度略快，且**预训练遗忘更少**；但 1 epoch 内 **SFT fit/复读/校准落后全参**（rep-4 0.260 vs 0.066）。Day 8 可做 r=12（≈1.80% 参数，仍 <2%）或 2 epochs 深化，用单变量对照裁决。

## 7. GGUF → Ollama → 本地 demo

**导出**（`tools/export_gguf.py`）：直接把 checkpoint 映射成 Llama GGUF（`token_embd / blk.N.attn_q… / output`），F16 312MB / 147 tensors；tokenizer 从 32k BPE 的 vocab+merges 写入（`model=gpt2`, `pre=gpt-2`）。
- **关键坑**：llama.cpp 的 `LlamaModel.permute` 会对 q/k 权重按 head 重排 `[n_head,2,head_dim/2,in] → swapaxes(1,2)`；漏掉时模型能加载但"前几个词正常、随后复读"（F16/Q4 同病）。补 `permute_qk()` 后恢复。

**Ollama 模型**（用户级服务 `OLLAMA_HOST=127.0.0.1:11435`，系统服务无写模型目录权限）：

| 模型 | 量化 | 大小 |
|---|---|---|
| `pretrain-lab-sft-v2` | F16 | 326MB |
| `pretrain-lab-sft-v2-q4` | Q4_K_M | **103MB** |
| `pretrain-lab-sft-v2-q8` | Q8_0 | 173MB |

**GGUF 与 PyTorch 对拍**（raw 模板 / greedy / CPU）：identity = "我是minimind，一个由个人开发者开发的智能助手…"、math-mul = "7 乘以 6 等于 72。"、2027 = "2027 年没有世界杯。世界杯每四年举办一次，所以 2027 年没有冠军。"、ML = 一句话——与 PyTorch v2 一致，证明导出映射正确。

**本地聊天页**：`tools/app_stdlib.py`（stdlib HTTP + Ollama，避开 Gradio 镜像下载卡死），`http://127.0.0.1:7860`；另保留 `tools/app.py`（Gradio 版，装好 Gradio 后可用）。Q4 demo（系统提示 + T0.7/top_p0.9，CPU 验证 transcript 见 `reports/2026-11-19-day7-deploy.log`）：
- identity → "我是minimind，一个由个人开发者开发的智能助手…"（本次 transcript；系统提示下多为 minimind/jingyaogong，T0.7 仍可能波动）
- ML → 一句话
- math-mul → "7 乘以 6 等于63。"（**算术不可靠**；raw greedy 为 72，全参 PyTorch 也是 72——错在模型，不在量化）
- 2027 → "2027 年没有世界杯。世界杯每四年举办一次，所以 2027 年的冠军尚未举行。"（语义正确）
- en-fluency → "I'm sorry, but I'm unable to provide information about the ocean. The ocean is a vast and vast body of water…"（**先拒答后描述**；rubric 判拒答，已知限制）
- 速度（CPU）：Q4 80~100 token 约 0.03~0.25s；GPU 空闲后会更快。

| 题库 ≥16/18 | **15 关键词 / 16 语义** ⚠️（refuse-unknown 关键词 gap） | 15 关键词 / 16 语义 ⚠️（capability/translate 回归） |

| 结论 | **部署**（综合最佳） | 消融（不部署） |

> 严格关键词口径下两版都是 15/18（差 1 题）；语义 rubric 下都是 16/18。**v2 的失败是 math-add/math-mul（真能力缺陷），v2b 的失败是 capability/translate（数据分布代价）**——两者都不是"全绿"，报告不掩盖。

- **v2b 不部署**：数学修好但 rep-4 0.117、translate/capability 回归；作为消融证据。
- **v1 不部署**：关键词 16/18 最高但 rep-4 0.131、校准编造、格式/拒答差；规则分高估质量。
- **en-fluency 拒答**：v1/v2/v2b 都未修好；Day 8 可做英文正例上采样/通用拒答降采样，或用 DPO。
