# LoRA r=12 · 2 epochs — capacity 曲线补点（2026-11-21，spec 2026-11-21 T2）

## 1. 配置（唯一变量 = epochs）

```bash
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True .venv-pre/bin/python -I tools/sft.py \
  --init-from out/main140m/last.pt --data-dir data/sft-mix-v2 --run-name sft-lora-r12-5e4-2ep \
  --out-dir out/sft-lora-r12-5e4-2ep --batch-size 8 --grad-accum 8 --base-lr 5e-4 --warmup 100 \
  --target-tokens 500e6 --eval-every 250 --eval-iters 20 --eval-batch-size 8 \
  --sample-every 500 --ckpt-every 250 --lora-rank 12 --lora-alpha 16 --max-minutes 320
```

对照 r12-1ep（Day 10）：同底座/同数据（v2）/同 lr 5e-4/同 bs，**唯一变量 = target-tokens 250e6→500e6**（total_steps 3,815→7,630；数据为随机偏移采样，等期望 2× 覆盖）。

## 3. 判定（spec §5 预注册）

- 主判据 = val < 1.75 → epochs 主因；≥1.80 → 容量主因。**实测 1.7921 → 落 1.75~1.80 档 = "epochs 有贡献但未收敛过半"。**
- **容量曲线三读数**：全参 1.6038 / r8-1ep 1.8253 / r12-1ep 1.8054 / **r12-2ep 1.7921**——rank +0.59% 买 −0.020，epochs ×2 买 **−0.013**。**两个维度单独加码的边际收益都已枯竭**（距全参仍差 0.19）；"1 epoch 低秩适配器学不会首次对齐"的结论修正为"低秩 × 少 epoch 的组合不足，且单独补任一维都不够"。
- **能力维度 2ep 有实效**：holdout v3 人工 42→48（+6，与 v2d 持平）、rep-4 0.249→0.176、关键词 54→56——**若未来用 LoRA，2 epochs 是下限配置**。
- 不部署（维持 v2e-q8）：val/复读读数仍劣于全参部署版，且部署无增量需求。
