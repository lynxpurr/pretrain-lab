## 题 1 · "等式行 ≥3" 这个豁免口径为什么能区分练习列表与叙述罗列？它什么时候会失效？

v2b 全量豁免数学列表（23,253 条）修回了算术但 rep-4 抬到 0.117；v2c 收窄为"assistant 等式行 ≥3 才豁免"（9,693 条）。为什么"行里含 `3+5=8` / `7 乘以 6` 这类算式"能挑出真正教算术组合的样本，而"用户句含数学关键词+数字"不能？这个启发式对哪类样本会失效——文字应用题（鸡兔同笼不带算式行）、几何证明、代数推导——它们在 v2c 里被如何处理，损失了什么？（提示：练的是"哪条样本在教哪个具体组合"；叙述型数学教的是推理流程，140M/1 epoch 学不动推理流程但学得动组合记忆——这正是判据里 math-add/math-mul 是"纯数字"的原因。）

**自答**：等式行能区分，是因为"教一个具体算术组合"的样本必须把组合显式写成 input-output 对（`3+5=8`），模型作为统计学习器只能从同现里记组合；叙述型数学（应用题讲解/概念罗列）教的是推理流程与术语，等式只是点缀。eqrows≥3 实际测的是"等式是不是主体内容"这个练习行为，而"数学关键词"测的是话题标签——几何证明、概念解释都命中关键词但不教组合（关键词池 26,184 vs 等式池 9,693，命中率差 2.7×）。**失效域**：①纯段落推理的应用题（等式不在编号行首，LIST_LINE_RE+EQ_ROW_RE 双条件漏掉）；②几何证明（∠/∥/△ 符号不在 EQ_ROW_RE）；③代数推导（x/y 变量等式不匹配纯数字算式）。它们在 v2c 走 1/5 降采样，损失的是"多步推理流程"暴露量——但 140M/1 epoch 本来学不动流程（v2b 修复的只是组合记忆），所以判据才定在 math-add/math-mul（组合）而非 reason tag。边界：形状 proxy 功能的前提是**用数据验证过命中面与功能面对齐**——侦察三轮迭代（rows≤4 为 0 → 行数分桶 → 等式行分桶）就是验证过程。

## 题 2 · 降采样作用在"读到的行"而不是"全库"——预算截断与降采样怎么交互？

英文拒答全库 21,345 条，但 16,601 条集中在 rows 800k-900k 桶，而 250M token 预算在 n_read≈810k 就停——所以 v2c 的"拒答降采样 50%"实际只砍了训练集里的 2,383/4,722 条。为什么对训练效果而言这仍是"降采样 50%"？如果哪天把 `--max-tokens` 提到 300M（会读到尾部拒答桶），同样的命令会砍掉多少？这种"采样规则 × 数据顺序 × 预算"的交互，在改预算时怎么避免踩坑？（提示：训练集只由读到的行构成；"规则作用域 = 训练集"而非"全库"；改预算 = 改训练分布，改动前后要做 meta 对账。）

**自答**：等价性的准确表述是——**模型只见训练集，而训练集 = 读到的行**。"对 seen 砍 50%"直接改变训练集构成（拒答密度 1.16%→0.40%）；没读到的 16,601 条无论如何不进训练集，砍不砍对模型无差别。所以规则作用域天然是训练集而非全库。若把 `--max-tokens` 提到 300M：会读到 800k-900k 桶（16,601 条拒答 + 29,812 条 helpful 同时涌入）→ 同一命令砍掉 ~8,300 条拒答，且 plain/helpful 构成同步漂移——**"同一参数"在不同预算下是不同的数据集**，不是参数错了而是作用面变了。避坑三步：①改预算前先分桶扫描（规则作用对象的全库分布，10 行脚本）；②构建后 meta 对账 seen/kept/dropped 三数并与旧版 diff；③把"分布随预算漂移"当常态写进 meta 备注（v2c 的 PROVENANCE 节就是这么记的），跨版本可比性靠对账而不是靠"参数相同"。

## 题 3 · 英文正例上采样的稀释效应——同 token 预算下挤掉了什么？

英文会话平均 ~138 token（584 chars @ 4.23 chars/token），远短于中文会话（~600 token）。v2c 上采样让对话总数从 404k 涨到 587k、监督占比 78.15%→76.16%——同一 250M token 预算被英文短会话分走了 ~3.3M token。这挤掉的主要是哪类样本？"英文能力↑"会不会以"中文能力↓"为代价，用什么读数验证？（提示：预训练 val 是文档级留出的双语混合——预训练 PPL 是中文稀释的中哨；更细的验证 = 分语言 val 或题库 zh tag 分项对比 v2/v2c；算一笔"挤掉预算"的账。）

**自答**：挤掉的主要是**排在数据流后部的 plain 中文长会话**——预算 250M 固定，英文正例净多写 ~2.3M token（16,377 条选中 ×1 增量），主数据流更早到达 break；v2c 会话数 587k vs v2 ~404k 也印证"每个 token 装的会话变多"（英文会话 ~138 token vs 中文 ~600 token）。监督占比 78.15%→76.16% 是同一现象的另一面：短会话多 → 模板头尾（user/填充）占比升。**稀释幅度有账可算：英文净增 ≈0.9% 预算，这是稀释的上限**。验证三读数：①预训练 val PPL（双语混合）16.184 vs v2 16.185 持平——粗信号；②**题库 zh tag 分项**：v2c 的 fact-zh/identity/explain/summary/format/code/reason/zh-fluency 九题全过、与 v2 通过面完全相同，无中文回归证据（六版评测里唯一回归的 translate-en2zh 是"方向"问题不是中文能力问题）；③标准工具 = 分语言 val（把 pretrain val 按中英切块分别算 PPL）——本轮没做，若未来英文占比再加大（>5% 预算）就必须上。结论：本轮稀释无害（上限 <1% + zh 分项零回归），但"上采样必算稀释账"要成为固定动作。
