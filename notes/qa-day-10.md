## 题 1 · "数据重建 bit-for-bit 一致"证明了什么、没证明什么？

Day 10 终检把 §10 的 v2e 构建命令原样重跑到 `/tmp`，4 个文件 sha256 与 `data/sft-mix-v2e/SHA256SUMS` **逐条相同**、meta 除耗时/时间戳外全字段相同。为什么这是"最便宜的可复现性证据"？它证明了流水线的哪一层性质（确定性/输入不变性/…），又**没有**证明什么（换机器、换 tokenizer 版本、换 Python 版本还成立吗）？要让这条证据成立，构建脚本里至少要有哪三样东西是确定的？（提示：随机种子、文件遍历顺序、hash 函数的选择——为什么不能用 Python 内置 `hash()`？）

**自答**：它证明的是**流水线确定性**：同一份输入 + 固定随机种子 + 固定文件遍历顺序 + 固定 hash 函数 → 逐字节相同输出；4/4 sha256 与 meta 全字段相同说明构建没有隐藏的时序/环境依赖。它**不证明跨环境可移植**：换 tokenizer 文件、Python/依赖版本、机器，仍可能不同；所以对账要连"输入指纹"（SHA256SUMS、ckpt sha、代码 commit）一起记。三样必须确定：**seed、遍历顺序、hash 函数**——用 `blake2b` 而非 Python 内置 `hash()`，后者受 `PYTHONHASHSEED` 随机化，跨进程不稳定。

## 题 2 · 量化保真度为什么必须抽检"新学能力"，而不是"能对话/强先验"？

v2e 三档对拍：F16 5/5 逐字一致；Q8_0 保住 math 42 / translate 中文；**Q4_K_M 把 42 打回 72、translate 打回英文原句**。而 Day 7 的 v2 对拍里 Q4 与 PyTorch 一致，给人"量化无害"的错觉。为什么同一个 Q4 档在 v2 上"忠实"、在 v2e 上"吃掉能力"？"弱记忆 vs 强先验"在这个现象里各指什么？如果只验收"能加载、能对话、identity 题答对"，会漏掉什么？（提示：Day 7 的 v2 错误答案 72 本身就是基座强先验；量化噪声只冲掉与强先验冲突的新映射。）

**自答**：量化噪声会冲掉**弱记忆**——新学、且与基座强先验冲突的映射（42、中文翻译）；Q4 的误差足以让模型退回强先验（72 = 6×12、英文原句）。v2 时代 Q4"与 PyTorch 一致"是假象：它的错误答案 72 本身就是强先验，量化冲不掉；v2e 的 42 是弱记忆，一冲就回退。只验收"能加载/能对话/identity 对"会漏掉**全部新学能力**——验收必须是 F16 逐字对拍（链路）+ 目标量化档在"本版新修复题"上的抽检（math 42 / translate 中文 / refuse 表述）。

## 题 3 · 八版终表的"含记忆/干净"标注——去掉它，哪两个结论会被误读？

v2~v2d 的题库分含与 18 题原句撞车的 extras 样本，v1 的 16/18 与 v2e 的 17/18 才是干净读数。如果终表只按分数排序、不标"含记忆/干净"，读者会得出哪两个错误结论？反过来，**保留标注**会不会让"v2c 17/18"看起来比实际更差——应该怎么正确读它？（提示：①"v2c 17/18 > v2e 17/18 所以 v2c 更好"？②"v2 15/18 < v1 16/18 所以数据迭代退步"？③同一版本内"记忆修复"与"泛化修复"如何区分——去污前后的差值给的是下界还是上界？）

**自答**：去掉标注会误读两件事：①"v2c 17/18 与 v2e 17/18 相同，所以 v2c 一样好"——v2c 的 17 含记忆样本，v2e 是去污后的干净 17，**两者不可横比**；②"v2 15/18 < v1 16/18，所以数据迭代退步"——v2 的 15 也含记忆成分，v1 无 extras 才是干净基线。保留标注不是贬低 v2c：它标记的是"不可比"，v2c 的价值在**机制验证**（选择性数学保护 + en-fluency 首修）。去污前后的差值只能当记忆贡献的**下界**（v2 vs v2e 同时改了多件事），不能当精确占比。
